# 安全审计清单

## 一、认证与会话

- [ ] 凭证生命周期明确：谁签发、多久失效、如何吊销
- [ ] 吊销是否精确到正确的粒度（按任务/代次 vs 全量）
- [ ] 吊销后旧凭证是否真的失效（查库里有没有过滤 `revoked_at`）
- [ ] 是否存在凭证被复用的路径（环境变量快照、会话恢复、缓存）
- [ ] 重放防护：一次性凭证是否真的一次性
- [ ] 会话固定 / 会话劫持：登录后是否轮换会话标识
- [ ] 认证失败的错误信息是否泄露内部状态（区分"不存在"和"已吊销"要有意为之）
- [ ] token 是否被写入日志、URL 参数、错误上报

**高危信号**：文凭证在多个任务/请求间共享；凭证通过环境变量跨进程传递且不轮换。

## 二、授权与隔离

- [ ] 每个资源读取都有归属校验，不只看"登录了没有"
- [ ] **多租户隔离**：workspace/tenant 过滤是否在所有查询上强制存在
- [ ] IDOR：改为别人的资源 ID 能否读到/改到
- [ ] 角色与权限的判断是否在服务端，不依赖前端
- [ ] 多态关联（如 assignee_id + assignee_type）是否校验类型与归属匹配
- [ ] 内部接口是否也做了鉴权（不能默认"内网可信"）
- [ ] 批量接口是否逐个资源校验，而不是只校验第一个
- [ ] 越权删除 / 越权邀请 / 越权查看成员列表

**高危信号**：查询里缺 workspace_id 过滤；权限判断散落在多个 handler 各自实现。

## 三、输入处理

- [ ] SQL 注入：是否有字符串拼接 SQL（sqlc 之外的手写查询重点看）
- [ ] 命令注入：`exec` 的参数是否来自用户输入，是否用参数数组而非 shell 字符串
- [ ] 路径穿越：文件路径是否做规范化并限制在允许根目录内
- [ ] SSRF：用户可控 URL 是否限制目标（内网地址、云元数据端点）
- [ ] XSS：用户内容是否直接插入 HTML（尤其 `dangerouslySetInnerHTML`）
- [ ] 反序列化：是否解析不可信的结构化数据到强类型对象
- [ ] 文件上传：类型、大小、内容校验，存储路径不可控
- [ ] 正则 DoS（ReDoS）：用户可控输入进入复杂正则
- [ ] 请求体大小限制、字段长度限制、数组长度限制

## 四、密钥与敏感数据

- [ ] 仓库里有没有硬编码的 token / 密钥 / 证书（含测试文件、示例配置、commit 历史）
- [ ] 密钥是否通过环境变量或密钥管理注入，不进代码
- [ ] 日志是否打印请求头、请求体、凭证、个人信息
- [ ] 错误响应是否泄露堆栈、SQL、内部路径
- [ ] 前端 bundle 是否打包了服务端密钥（检查构建产物）
- [ ] 敏感数据是否加密存储（凭证、个人身份信息）
- [ ] 数据导出 / 备份是否脱敏
- [ ] 崩溃上报是否包含敏感上下文

## 五、依赖与供应链

- [ ] 已知漏洞扫描（语言对应工具：`go list -m all` + govulncheck、`pnpm audit`）
- [ ] 锁文件存在且与 manifest 一致（防止构建不可重现）
- [ ] 依赖是否来自可信源，有无 git 地址或 tarball 直引
- [ ] 安装脚本（postinstall）是否可控
- [ ] 是否存在明显废弃/无人维护的关键依赖
- [ ] 依赖许可是否与项目分发方式兼容

## 六、速率与资源

- [ ] 认证接口有速率限制
- [ ] 昂贵的接口（搜索、导出、批量操作）有配额
- [ ] 分页有上限，不能 `limit=1000000`
- [ ] 用户可控的并发/递归/深度有约束
- [ ] 长任务有超时和取消机制
- [ ] 失败重试有退避，不形成风暴

## 七、可审计性

- [ ] 关键操作（登录、权限变更、删除、导出、凭证签发/吊销）有审计日志
- [ ] 审计日志记录主体、对象、时间、结果，且不可被普通用户篡改
- [ ] 日志中的标识符足以对账（请求 ID、实体 ID、代次）

## 输出格式

每条安全发现必须包含：

```
- 风险类型：（越权 / 注入 / 泄漏 / 凭证 / 供应链 …）
- 位置：文件 + 行号
- 可利用性：谁能触发、需要什么前提、影响范围多大
- 证据：代码路径 或 实际复现
- 若利用：会发生什么（读什么 / 改什么 / 拿什么）
- 修复方向：具体改哪里，不是"加强校验"
```

**可利用性必须诚实判断。** 不可利用的"理论风险"标为 P3，不要为了凑数升到 P0。

## 常见误判

- 把"没有 CSRF token"当高危——如果认证用 header 而非 cookie，本身就不受影响
- 把"返回了内部错误信息"当 P0——先判断是否包含敏感数据
- 把"依赖有漏洞"当 P0——先确认该依赖路径是否实际被调用
- 把"缺少速率限制"当普遍高危——只对可达且昂贵的接口成立
