# 质量工程师检查清单

## 测试策略分层

| 层 | 目标 | 谁写 | 覆盖重点 |
|---|---|---|---|
| 单元 | 函数/类 | 墨子 | 边界条件、异常路径 |
| 集成 | 模块间 | 墨子/包公 | 契约、数据一致性 |
| 端到端 | 用户旅程 | 包公 | 完整路径、状态持久化 |
| 故障注入 | 失败恢复 | 包公 | 超时、错误返回、部分失败 |
| 回归 | 无退化 | 自动 | 关键路径、性能基线 |

## 必检清单

### 1. 边界条件
- 空输入、null/undefined、超长、溢出
- 并发访问（竞态、死锁）
- 网络失败（超时、断连、重试风暴）
- 数据损坏（部分写入、脏读）

### 2. Agent 特有检查
- token 失效后行为（是重试还是报错？错误码够不够区分？）
- checkpoint 恢复正确性（Agent A 中断 → Agent B 续跑，状态一致吗？）
- Agent 产出格式（机器可继续加工还是只给人看？）
- 人类审批点（设计在高价值决策还是每个小步骤？）
- 工具调用错误（Agent 能自行恢复还是必须人介入？）

### 3. 安全
- 输入验证（SQL 注入、XSS、命令注入）
- 权限边界（谁能调什么 API？）
- 敏感数据（日志里会不会泄漏 token/凭证？）
- 速率限制（防止资源耗尽）

### 4. 性能
- 分页与懒加载（不要一次性拉 10K 条）
- 数据库索引（慢查询、全表扫描）
- 并发数（峰值能撑多少？降级策略？）
- 冷启动（首次加载时间 vs 热启动）

### 5. 可观测性
- 日志分级（error / warn / info / debug）
- 关键路径 trace ID 贯穿
- 业务指标（不是机器指标：不是 CPU 90%，而是"任务成功率"）
- 告警阈值（谁来响？响几次？升级路径？）

### 6. 界面状态完整性
- 六态齐全：默认 / 空数据 / 加载中 / 错误 / 无权限 / 超长文本+窄屏
- 缺少空态或错误态视为功能未完成，不是"后续优化"
- 必须有截图证据，不接受"我看了没问题"
- 布局类问题（溢出、塌陷、错位）用截图或视觉 diff 判定，不靠文字描述
- 移动端断点单独验证，不能只测桌面宽度

## 验收报告格式

```
## 验收结论: ✅ PASS / ⚠️ CONDITIONAL / ❌ FAIL

### 测了什么
- 列出覆盖的测试项和结果

### 没测什么（已知盲区）
- 明确说出来，不要隐瞒

### 风险点
- 即使 PASS 也可能有风险的地方

### 证据引用
- 日志片段、截图、测试 ID
```
